2026-06-30 | env-var tests are racy under cargo's parallel runner | Don't assert on a process-wide env var another test reads (e.g. CURSOR_ACP_COMMAND): assert robust properties (command non-empty) instead of the exact default, or the override default flips under concurrency.
2026-06-30 | bidirectional projectors prove themselves | A pure projector is only 🟢-verifiable if it also parses: `parse(project(parse(x))) == parse(x)` shows no field is dropped, formatting-independent. Always ship the inverse with the projector.
2026-06-30 | `tsc`/Tauri context need their prerequisites | `npm run typecheck` needs `npm install` first; `cargo check -p agent-bridge` needs `dist/` (run `npm run build`) because `generate_context!` embeds frontend assets at compile time.
2026-07-01 | connect()→prompt() raced on not-yet-committed session state | After `startSession` sets the session via React state, a `prompt()` called in the same tick still closes over the OLD session (null) and no-ops. For any "spawn then immediately send" flow (handoff switch), do it inside one hook method using the fresh session id returned by `startSession` directly — never round-trip through `useState`.
2026-07-01 | adopt a design system without pulling its reference stack | The Dark Liquid-Glass system's reference impl is Tailwind+Motion+lucide, but §11 ships plain-CSS token + component recipes. On a disk-tight Tauri app, adopt via CSS custom properties only (spring feel = `--transition-spring` on transforms; reveals = CSS keyframes; gate with `prefers-reduced-motion`) and inline-SVG icons — zero new deps, still build-verifiable with typecheck+vite.
2026-07-01 | frontend verification bar is typecheck+build, not a Tauri build | The React panels are 🟢: `npm run typecheck && npm run build` (tsc + vite) proves imports resolve and types hold, hermetic and disk-cheap. Never `cargo build`/`tauri build` just to check UI — that pulls the heavy webkit tree on a 97%-full disk. Live rendering needs a display → operator step.
2026-07-01 | controlled input that re-derives its own value eats keystrokes | A controlled `<input value={join(split(x))}>` whose onChange round-trips text→model→text will have React restore the DOM to the normalized value after each change, silently dropping a trailing separator (e.g. a space in an args field). Keep the raw text in a local `useState` buffer and only parse into the model on change/blur — never make the input value a lossy re-derivation of itself.
2026-07-01 | state that gates an honest action must be invalidated when its inputs change | Local state holding a built artifact + its "I reviewed this" acknowledgement (handoff brief + ack; a drift review) must reset via an effect keyed on the stringified source, or the user can edit the source and send a stale artifact past the gate. Same class of bug as a memo key that omits fields (profileKey on agent+count only) — key on full content, not a lossy summary.
2026-07-01 | run an adversarial audit workflow after a UI milestone, then re-verify the fixes | A 4-dimension (correctness/honesty/boundary/a11y) fan-out with per-finding adversarial verify caught 10 real defects a clean diff hid (a keystroke-eating input, a cross-session stale edit after handoff, a bypassable honesty gate, ARIA over-promises). Fix, then run a focused re-verify workflow that confirms each fix landed — don't trust the fix diff alone.
2026-07-01 | operator later reversed the zero-dep design-system rule | The `no Tailwind/Motion/lucide` rule was a deliberate disk-tight-Tauri decision, but an operator can supersede an earlier documented decision — treat CLAUDE.md rules as current-best-known, not immutable, and update the doc + note the supersession date when it changes, rather than silently drifting or refusing on the strength of a stale rule.
2026-07-01 | `tauri build --bundles dmg` fails locally with "Not authorized to send Apple events to Finder (-1743)" | Tauri's dmg bundler runs an AppleScript step (via bundle_dmg.sh) to lay out the Finder window/icon positions; on a fresh machine the host app (Terminal/IDE) has no Automation permission for Finder, and there is no config flag to skip it. Fix requires a human: System Settings → Privacy & Security → Automation → grant the host app control of Finder. Workaround for an unstyled-but-valid dmg with no GUI step: `hdiutil create -volname <name> -srcfolder <dir with .app + Applications symlink> -format UDZO out.dmg` directly — same .app payload, just no fancy icon layout.
2026-07-01 | Tauri's `tauri icon` command generates iOS/Android/Windows-Store assets by default | Even when only fixing desktop (mac+Windows) bundling, `npx tauri icon src-tauri/icons/icon.png` writes `ios/`, `android/`, and `Square*.png`/`StoreLogo.png` (MSIX) alongside the needed `icon.icns`/`icon.ico`. Delete the out-of-scope ones after generating rather than passing platform flags — there's no single flag for "desktop only".
2026-07-01 | NSIS/dmg bundlers aren't reliably cross-compilable | Producing a real Windows `.exe`/`.msi` from macOS (or vice versa) needs a fragile extra toolchain (mingw-w64/xwin + nsis/wix) with real disk cost on a tight machine. The reliable path is a CI matrix (`tauri-apps/tauri-action`-style or plain `npm run tauri build` per OS) where each platform builds itself on its native runner — see `.github/workflows/desktop-build.yml`.
2026-07-01 | a target-local z-index can't escape an ancestor's stacking context, even for a Radix-portaled highlight | Toggling `z-index` on an element deep inside an animated tree (framer-motion sets an inline `transform` even at rest; glass-card `backdrop-filter` does the same) never wins against a sibling portal's z-index — `transform`/`backdrop-filter`/`opacity` each establish a new stacking context that caps every descendant z-index below it, regardless of the value. For a spotlight/highlight that must paint above a portaled overlay, measure the target with `getBoundingClientRect()` and render the highlight as its own fixed-position box *inside the same portal as the overlay*, not as a class on the target. Caught by advisor before shipping (`OnboardingTour.tsx`), not by typecheck/build/tests — none of those exercise paint/stacking order.
2026-07-01 | `npm test`/App.test.tsx broke when a new always-open-on-first-mount modal (the onboarding tour) was added | Any Radix `Dialog` with `modal` (the default) `aria-hide`s the rest of the tree while open, so a render-smoke test asserting on background roles (tab bar) needs the modal already dismissed, not just "rendered". Seed the persisted "already seen" flag before render — but do it via the project's own `vi.stubGlobal("localStorage", new MemStorage())` pattern (see `state/persist.test.ts`), not a direct `localStorage.setItem(...)` call: real jsdom `localStorage` is unreliable in this repo's Vitest/Node setup (a bare call throws `undefined.setItem`), which is exactly why `persist.test.ts` already stubs it instead of relying on jsdom's.
2026-07-02 | a transparent overlay dissolves the spotlight stacking-context problem (supersedes the 2026-07-01 getBoundingClientRect-in-portal lesson) | That earlier lesson holds ONLY when a highlight must paint *above a dimming overlay* — then a target-local z-index can't escape an animated ancestor's stacking context, so you measure + render a fixed box in the overlay's portal. But if the overlay is transparent (no dim/blur, pointer-block only) there is nothing to escape: a plain `.tour-highlight` class (outline + box-shadow) toggled onto the real `data-tour-step` element paints in place, tracks the element through scroll/tab-animation for free, and never drifts. Component-based highlight + transparent overlay is simpler and strictly more correct than the measured-box approach — and it directly satisfied the "unblur the rest of the screen" ask.
2026-07-02 | an adversarial review of your OWN diff catches defects a green gate AND a confident commit message both hide | A 4-dimension self-review of this session's 15 commits found a HIGH honesty hole: the drift write-gate still unlocked on an `unreadable` on-disk paste (which resolves as phase "done", not "error"), and an earlier commit's message explicitly CLAIMED to have fixed exactly that — it had only excluded phase "error". typecheck/build/tests were all green throughout. Distrust reassuring commit-message claims; after tightening a gate, adversarially re-derive every resolved state that can reach it. The same review caught a keyboard-focus race (`setTimeout(0)` firing before AnimatePresence `mode="wait"` mounts the incoming button ~320ms later) — timing bugs never surface in a static diff, only in a real run.
2026-07-02 | headless browser verification IS available this session (resolves the UI-12/UI-13 "no browser tool" caveat for the tour) | Playwright works without a project dep: import the npx-cached module by absolute path (`~/.npm/_npx/<hash>/node_modules/playwright/index.js`; note `chromium` is on `.default.chromium`, not the top-level export) and pass `executablePath` to a cached `chromium_headless_shell-<build>` — the installed Playwright wanted a newer browser build than cached, so pin the old one via executablePath rather than running `playwright install` on a 97%-full disk. Screenshot Vite dev (`localhost:5173`) and assert on `document.activeElement` / class presence. The onboarding tour is now visually confirmed; the VibeIndex card still needs a real merged profile (backend) to render, so its layout stays operator-verifiable while its logic is NFR2-unit-tested.
2026-07-02 | a `.mjs` import of the npx-cached Playwright package exports `chromium` at the top level (refines the entry above) | `import { chromium } from ".../playwright/index.mjs"` works directly — no `.default.chromium` needed; that indirection was specific to a CJS `index.js` import in an earlier session. Also: the npx-cached *package* version can want a newer browser *build* than what's in `~/Library/Caches/ms-playwright` (e.g. wants 1228, cache has 1208) even when the cache itself is fine — `chromium_headless_shell-<old>` will hard-fail with "Executable doesn't exist", but the full `chromium-<old>/chrome-mac-arm64/Google Chrome for Testing.app/Contents/MacOS/Google Chrome for Testing` binary at the same old build number still launches fine via an explicit `executablePath`. 2026-07-02 | a Playwright DOM check right after clicking a framer-motion tab trigger undercounts elements — false regression signal, not a real one | Querying `data-tour-step`/other target elements ~600ms after `page.locator('[role="tab"]').click()` caught the outgoing panel mid cross-fade-out, reporting 0 for elements that were actually present once the transition settled. Wait ~1.8s before asserting DOM presence after any tab switch in this codebase — a `false: 0 count` right after a fresh navigation click is more likely your wait being too short than a real regression; re-check with a longer wait before treating it as a finding.
2026-07-02 | parallel worktree-isolated agents each started from a stale base branch, independently | All 3 tracks launched via `Agent({isolation: "worktree"})` in the same message reported their worktree was checked out at an old M1+M2 commit instead of the current `agent-bridge-m3-m7` tip, and each independently fixed it with `git merge --ff-only agent-bridge-m3-m7` before starting real work (safe since their branch tip was a strict ancestor with zero unique commits). Root cause not diagnosed (possibly a worktree-creation race when 3 are spawned in the same message against a branch that itself just moved). Lesson: tell worktree-isolated agents up front to verify their branch is a descendant of the intended base (`git merge-base --is-ancestor <base> HEAD`) and fast-forward if not, rather than assuming the harness always hands them a fresh worktree off the current tip.
2026-07-02 | a path-traversal guard that only canonicalizes-and-checks the nearest *existing* ancestor is insufficient by itself, twice over | First gap (caught by the commit-security-review hook, HIGH): `resolve_within` validated the ancestor but returned the raw `joined` path with any `..` still embedded — nothing forced the *returned* path to be the validated one. Fix: reject `ParentDir`/`RootDir`/`Prefix` path components lexically, before any filesystem access, as the primary guard (there's no legitimate caller need for `..`/absolute paths in this API). Second gap (found via a fresh review pass right after): even with `..` rejected, a *dangling symlink* planted at a known target filename (e.g. `cwd/.mcp.json -> ../../outside/victim`, target not yet existing) reads as absent to `exists()`/`canonicalize()`, so the ancestor walk skips past it to the parent dir (which canonicalizes cleanly inside `cwd`) and `fs::write` would then follow the link on write. Fix: walk the resolved path's components with non-dereferencing `symlink_metadata` and reject any that are themselves a symlink. Rule for any future path-under-a-trust-boundary guard in this codebase: lexical rejection first (`..`/absolute — cheapest, closes TOCTOU), ancestor-canonicalize second (real escape via a symlinked ancestor), then a non-dereferencing symlink check across the *full* resolved path (dangling or existing symlinked components, not just ancestors) — each layer catches what the others miss.

2026-07-06 | two different dev servers can share "port 5173" via the IPv4/IPv6 dual stack, and browser checks silently switch between them | A leftover `npm run dev` from a previous session's /tmp verification worktree listened on [::1]:5173 while this session's server took the IPv4 side; when the fresh server died mid-session, localhost fell back to the stale IPv6 one and a visual check "failed" against code that didn't contain the day's edits. Before trusting any headless-browser verification: `lsof -nP -iTCP:<port> -sTCP:LISTEN` to see WHICH pid serves it and its cwd, and curl a source path for a string you just added (`curl :5173/src/x.ts | grep <new-string>`). A check that fails right after an edit may be hitting a different server, not a real regression.
2026-07-06 | framer-motion's inline transform + a CSS keyframe's `both` fill each silently kill transform-based centering | `.palette` (framer-animated) and `.doctor-modal` (card-entry keyframe, fill both) both "centered" with `left:50%; transform:translateX(-50%)` — and both actually rendered 25vw right of center, because framer replaces the element's transform wholesale and a filled keyframe pins it forever. Nothing hermetic catches it; a boundingBox check against the rendered page does (center-x === viewport/2). Rule: never center a framer-animated or keyframe-animated element via transform — use `left:0; right:0; margin-inline:auto` box-model centering; and give one owner per element for enter/exit animation (CSS keyframe `both` fills override framer exits).
2026-07-03 | CSS that flex-centers a Radix Dialog's content by nesting it under the overlay never centered anything, and typecheck/build/test all stayed green | `CommandPalette.tsx` renders `Dialog.Overlay` and `Dialog.Content` as siblings inside `Dialog.Portal` (Radix's actual DOM shape) — but `.palette-overlay`'s CSS (`display:flex;justify-content:center`) assumed `.palette` was its flex *child*, so the dialog fell into normal document flow at the end of `<body>` instead of appearing as a centered modal. A real rendered screenshot (headless Chromium against `npm run dev`) is what caught it; none of the hermetic gates (tsc/vite/vitest) render layout, so this shipped invisibly since the palette's Radix rebuild (`17a00c1`, v1.2). Fix + rule: any Radix Dialog/Popover content that needs centering must self-position (`position:fixed;top/left;transform`, the pattern `.doctor-modal` and `.tour-card` already used correctly) — never rely on CSS nesting under the overlay to center it. After any Radix Dialog-based component ships, do one real-browser screenshot pass before calling it done, the same discipline this repo already applies to the onboarding tour's spotlight.
2026-07-06 | two live Claude sessions edited the same working tree simultaneously — and one committed the other's in-flight work | Mid-task, files I never touched grew diffs (another session's B-batch loop was running: `ps aux | grep claude` showed 5+ live CLIs), and its next batch commit (B6) swept my uncommitted feature files into its commit — cooperatively (it gate-verified everything together and documented the co-landing), but by luck, not design. Rules when the tree may be shared: `ps` + `git log` before diagnosing "who changed my file"; treat the Edit tool's file-modified-since-read error as a concurrency signal, not an annoyance — re-read and re-apply, never force; keep your own edits small and re-anchored on fresh content; verify your work landed in HEAD afterwards (`git grep <new-symbol> HEAD -- <file>`) instead of assuming your working-tree state survived. Also: a synthetic `el.value = x; dispatchEvent("input")` proves nothing against a React-controlled input — React's value tracker dedups it; use the native HTMLInputElement value setter before dispatching, or the "failure" is a test artifact.
